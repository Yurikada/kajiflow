# KajiFlow

判断ハードルを最小化した、個人向けの家事実行システム。FastAPI + SQLite + バニラJS（ビルド工程なし）で構成し、PC上に常駐させてスマートフォンからPWAとして使う。

家事管理ツールが続かない理由を「やることが多いから」ではなく **「毎回どれをやるか決めさせられるから」** と捉え、メイン画面に出すのは常に **今の1件だけ**、操作は **完了 / スキップの2択だけ** にした。

- 仕様の正本: [SPEC.md](SPEC.md)（データモデル・API・スケジューリング規則・各バージョンの設計判断）
- ステータス: 個人利用中。v5（購買記録・買い物リスト）まで実装済み

---

## 設計原則

優先順位つきで4つ。実装で迷ったときはこの順で決めている。

1. **判断レス** — 「何をやるか」を選ばせない。一覧を眺めて選ぶ操作を UI から排除する。
2. **サボり耐性** — 未実施が溜まっても、赤字・滞納件数・遅延日数といった**罪悪感を与える表示を一切出さない**。再開したら普通に「今の1件」が出るだけ。スケジュールは完了実績にもとづいて自然にずれていく。
3. **軽量・ローカル** — ORM もフロントのビルド工程も持たない。標準ライブラリの `sqlite3` を直接使う。
4. **エージェント連携可能** — REST API と、週次サマリの Obsidian 書き出しを持つ。

2 は機能ではなく**制約**である。「続けさせるために罰を与えない」という方針を UI 仕様として固定し、遅延表示を足したくなる誘惑を設計段階で塞いでいる。

## 主な機能

| バージョン | 内容 |
|---|---|
| v1 | 「今の1件」提示、完了/スキップ、今日のリスト、タスクCRUD、家事テンプレ、週次統計、PWA、ntfy によるプッシュ通知 |
| v2 | Obsidian Vault のタスクノートとの双方向連携（分類ヒューリスティック、完了の書き戻し） |
| v3 | Google Tasks 双方向同期（`sync_all()` を全体調停として実装） |
| v4 | 自治体のゴミ収集カレンダー連動（`schedule_type='calendar'` の合成タスク） |
| v5 | レシート画像の解析キューによる購買記録と、「そろそろ切れる」買い物リスト |

## スケジューリングエンジン

`app/engine.py` は**すべて決定的**に書いてある。乱数を使わず、現在時刻も暗黙参照せず引数で受け取る。同じ入力からは必ず同じプランが出る（テストで固定している）。

- **実績にもとづく間隔調整** — `adaptive=1` のタスクは、直近の完了間隔（最大5件）の EWMA（α=0.3）で実効間隔を求め、`[0.5×設定間隔, 2.0×設定間隔]` にクランプする。「2日ごと」と設定しても実際に3日周期で回っているなら、設定値ではなく実績側へ寄せる。
- **緊急度** — `経過日数 / 実効間隔`。1.0 以上を当日の対象にする。
- **予算充填** — 目安分数を積み上げ、1日の予算分数を超えたらそこで打ち切る。ただし**1件目は必ず入れる**。
- **プランの凍結** — 生成した当日のプランは日付単位で保存し、同日中は明示操作でしか作り直さない。日中にタスクを追加しても反映は翌日から。**「今日やること」が途中で増えないこと**を判断レス性の一部として扱っている。
- **スキップにペナルティを課さない** — その日のプランから外すだけで、前倒しも催促もしない。`skip` は実績として記録するが、**間隔学習の材料には使わない**（サボった記録で周期を歪めない）。
- **対象ゼロを正当な結果とする** — 無理に1件ひねり出さず「今日はやることなし」を返す。

## 技術構成

- **バックエンド**: Python 3.13 / FastAPI / uvicorn
- **データストア**: SQLite（`sqlite3` を直接利用。ORM なし）
- **フロントエンド**: 素の HTML / CSS / JavaScript（ビルド工程なし）、PWA（manifest + service worker）
- **外部連携**: Google Tasks API、Google Calendar API、ntfy（プッシュ通知）、Obsidian（Markdown 書き出し）
- **タイムゾーン**: Asia/Tokyo 固定（`zoneinfo`）。「今日」の境界は現地時間 0:00

Service Worker は静的アセットの cache-first のみで、**API レスポンスはキャッシュしない**（古い「今の1件」を表示しないため）。

## 動かし方

Python 3.13を使うWindows PowerShellの例です。リポジトリ直下で実行します。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install fastapi uvicorn pytest httpx tzdata
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8340
```

PCのブラウザで `http://localhost:8340/` を開きます。既存の起動スクリプト
`scripts/run_server.ps1` も既定では `127.0.0.1:8340` にバインドします。
スマートフォンからはTailscale Serveなどのアクセス制御されたHTTPS経由で接続します。
LAN上のHTTPアドレスではService Workerを利用できないため、PWAの利用にはHTTPSが必要です。

Google Tasks・Calendar連携には別途本人によるOAuth設定が必要です。
家事タスクの基本操作はGoogle認証なしで利用できます。

DB は `data/kajiflow.db` に自動生成される（gitignore 対象）。初回はタスクが空なので、管理画面からテンプレを選んで追加する。

`scripts/` に、朝のダイジェスト通知（ntfy）、週次サマリの Obsidian 書き出し、Windows タスクスケジューラへの登録スクリプトを置いている。

## テスト

```bash
.venv/Scripts/python -m pytest -q
```

テスト件数と所要時間はリビジョン・実行環境で変わります。エンジン側は緊急度計算、EWMA とクランプ、週次判定、予算充填、プランの決定性、スキップが学習に影響しないことを固定している。API 側は `TestClient` で next → complete → next の遷移、CRUD、テンプレ適用、再生成、統計、および v2〜v5 の各連携を検証する。テストは環境変数 `KAJIFLOW_DB` で一時ディレクトリの DB を使う。

## 設計上の判断（なぜそうしたか）

- **ORM を使わない** — テーブル数が少なく、クエリも単純である。マイグレーションは `db.py` に直接書いた方が、何が起きるか読める。
- **エンジンを DB 非依存の純関数にした** — スケジューリング規則はこのアプリで最も壊れやすい部分であり、DB を挟まずにテストできる形にしておきたかった。決定性を保証しているのはこの分離である。
- **通知を「送れなければ黙って終わる」設計にした** — PC が起動していない時間帯に Task Scheduler がエラーを溜め続けるのを避けるため、API へ到達できない場合は exit 0 で静かに終了する。
- **常駐サーバの実行時間制限を無制限にした** — Windows Task Scheduler の既定（72時間）のままだと、PC をつけっぱなしにして3日でサーバが停止させられる。

## 非目標・限界

- **アプリ内認証を持たない。** 既定はループバック接続。スマートフォンからはアクセス制御されたHTTPS経由で使い、APIをLANやインターネットへ直接公開しない。
- **マルチユーザーに対応しない。** 1人分のデータだけを扱う。
- 家事テンプレは日本の一人〜二人暮らしを想定した内容で、一般解ではない。
- レシート解析は外部エージェントによる解析キュー方式で、アプリ内に OCR・推論を持たない。
